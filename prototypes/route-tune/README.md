# 原型：走线和等长一起规划，对比占用的空间（一次性，看完即弃）

对应 [原型：走线和等长一起规划，对比占用的空间](https://github.com/immorcoding/PCB/issues/21)。只存在于分支 `prototype/route-tune`，不合并。

**要回答的问题**：走线和等长一起规划，比"先走完线、再找地方补蛇形"能省多少地方，样子你认不认可。

这个目录现在只有地基和基线：一套所有方案共用的构建脚本，底板 `0_base`（19 根线走完、没有蛇形），基线 `1_baseline`（在底板上走完再补）。协调版由后面的方案加进来，用的是同一套脚本和同一张指标表。

本文件里没有手抄的数字。各方案的数字在 `out/summary.md`（由 `build.py --summary` 生成），每个方案逐根的表在 `out/<方案>/tune.txt`。

## 怎么看

- **KiCad**：打开 `out/<方案>/routetune.kicad_pro`。板子已经由 `kicad-cli` 重新铺铜并保存。蛇形在 KiCad 里是普通的线段加圆弧（AD 里相当于手画的 Track + Arc），不是"调整图形"对象。
- **图**：每个方案 20 张，`<取景>_<层>.png`。取景有 `bus`（整组线）、`corridor`（两颗芯片之间）、`sdram`（SDRAM 封装下面）、`south`（MCU 下方）、`north`（MCU 上方）；层有 `L1`、`L4`、`L6`、`all`（三层叠在一起，半透明）。L1 红、L4 蓝、L6 绿；灰色实线框是封装外形，绿色虚线是规则区（AD 的 Room）；每根线的名字标在它自己的线上。图只作定性参考，数字看表。不同取景的比例不一样，只能在同一个取景里比两个方案。
- **表**：`out/<方案>/tune.txt`（逐根的长度、绕远、蛇形、检查结果、每根线为什么这样走），`out/summary.md`（各方案并排）。
- **重建**：`D:/KiCad/bin/python.exe build.py <方案>`（十几秒）。KiCad 开着那块板时脚本会停下不写，先关掉。

## 板子

- 六层 JLC06161H-3313E：L1 信号，L2 地，L3 电源（不走信号），L4 信号，L5 地，L6 信号。L2、L5 整层铺地。
- MCU `STM32H743IIK6`（UFBGA176+25）在左，SDRAM `IS42S32800J`（90 球 BGA）在右，封装边到边 5 mm，位置和 [上一个原型](../length-tuning/README.md) 相同，所有方案都不动。
- 两个规则区 `BGA_MCU`、`BGA_SDRAM`，各是封装外形外扩 1 mm，所有铜层。区内线宽 0.09、间距 0.09、过孔 0.30/0.15；区外线宽 0.1016、间距 0.127。线宽在出规则区边 0.3 mm 的直线上换（拐点离规则区边不到 0.3 mm 时在拐点换）。
- 19 根线：`FMC_D0`–`FMC_D15`、`FMC_NBL0`、`FMC_NBL1`（接 SDRAM 的 DQM0、DQM1）、`FMC_SDCLK`。没有原理图，网络直接指定在焊盘上。**SDCLK 上没有放串联电阻**（正式板上会有）。
- 等长要求：每根线对 SDCLK 在 ±2.5 mm 以内（是窗口，不是补到一样长），每根不超过 60 mm。长度由 KiCad 的 DRC 量，含过孔高度。

## 方案

| 目录 | 是什么 |
|---|---|
| `0_base` | 19 根线按最顺的路走完，不考虑等长，没有蛇形。基线的起点。 |
| `1_baseline` | 基线，[上一个原型](https://github.com/immorcoding/PCB/issues/15) 的做法：`0_base` 的走线一根不动，走完以后逐根在规则区外找直线段补蛇形。 |

### `0_base` 是怎么走的

- **换位**：两个字节通道没有对调（MCU 的 D0–D7 接 SDRAM 的 DQ0–DQ7）；每个字节通道里的位按"同一层不交叉"重新排了。换位表在 `out/0_base/tune.txt` 的第二列。
- **第 1 字节（D8–D15）和 SDCLK**：SDRAM 上对应的球在靠 MCU 的三列，全部在 L1 上直接走到，不打孔。只有 D10 的球在 MCU 第 3 圈，打狗骨孔走 L4。
- **第 0 字节（D0–D7）和 NBL0**：SDRAM 上对应的球在远离 MCU 的三列。MCU 这边在封装边上（封装外、规则区内）打孔换到 L6，从 SDRAM 封装下面穿过去，在球旁边打孔上来。D3 的球在 MCU 第 3 圈，狗骨孔走 L4。
- **NBL0、NBL1、D2**：球在 MCU 的上边和左上角，只能向北出，绕过 MCU 右上角再沿两颗芯片之间下来，所以最长。
- 过孔都在芯片的规则区里，两颗芯片之间没有过孔。每根线 0 个或 2 个过孔。

### `1_baseline` 是怎么补的

- 先补 SDCLK：目标是"最长的那根减 2.5 mm"，补到放不下为止。然后以补完的 SDCLK 为基准，把低于窗口下限的线从短到长逐根补到下限上面 0.05 mm。比窗口上限还长的线没法缩短，只能记下来。
- 蛇形只放在规则区外、线宽 0.1016、不短于 2.5 mm 的直线段上，先用离这根线中点最近的一段；腿间距 0.5 mm（半径 0.25）；能单侧就单侧，单侧不够才双侧；摆幅先按不超过 1.0 mm 找，放不下再放宽到 2.0 mm；一段放不完就接着用下一段。
- 守的间距和上一个原型一样：拐点到第一个圆弧 0.35 mm，蛇形到别的铜 0.19 mm，蛇形到规则区边 0.127 mm。放不下的部分不画，在表里记"没补够，还差多少"。

## 指标的定义（所有方案同一个脚本 `lib/metrics.py` 算）

| 指标 | 定义 |
|---|---|
| 长度 | KiCad 的 DRC 量到的长度（探针规则）：焊盘中心到焊盘中心的走线（直线和圆弧）加每个过孔在它连接的两层之间的高度 |
| 比 SDCLK | 这根线的长度减 SDCLK 的长度；绝对值不超过 2.5 算在窗口内 |
| 直连最短 | 两个焊盘中心之间只走 0°/45°/90° 的最短平面距离，不管任何障碍，不算板厚 |
| 蛇形补的 | 这根线上所有蛇形多出来的长度（画出来的长度减去被它替换掉的那段直线） |
| 不算蛇形的走线 | 长度减蛇形补的，也就是把蛇形拉直以后的长度（含过孔高度） |
| 绕远 | 不算蛇形的走线减直连最短：靠走法本身多出来的长度（含过孔高度） |
| SDRAM 下的蛇形 | 蛇形补的长度里，蛇形的铜落在 SDRAM 封装外形以内的那一部分（按铜的长度比例折算） |
| 凸包面积 | 两颗封装外形以外的所有总线铜（走线、圆弧、蛇形的中心线和过孔中心，三层叠在一个平面上）的凸包面积 |
| 外包矩形 | 同一批点的外包矩形的宽和高 |
| 扫过的面积 | 同一批铜各自外扩"半个线宽加 0.127 mm"之后合并起来的面积，0.05 mm 栅格；有三层合并和分层两种。凸包会把相距很远的线之间的空地也算进去，这个数不会，所以它对蛇形和线距更敏感 |
| 窄条里上下占 | 两个规则区之间那一条（x 19–22 mm）里，总线中心线在 y 方向（垂直于 MCU 到 SDRAM 的方向）的最大值减最小值；另有分层的 |
| 各层铜面积 | 每层总线走线的长度乘线宽之和（整根线，包括封装下面的部分） |

检查项（`metrics.json` 的 `checks`）：DRC 各类条数（未连接必须是 0，剩下的只能是长度超窗）；规则生效检查（往板的副本上放一个直角拐弯，看 DRC 报不报）；每条长度规则单独探测时是否匹配到 19 根线；`track_shape.py` 的五项；脚本从板文件量的间距、每根线是不是一条从球到球的单线、蛇形离别的网络和规则区边最近多少、拐点到第一个圆弧最短多少。

## 我自己定的、没有和你约定过的

1. **基线的摆幅上限 2.0 mm**（先按 1.0 找，放不下才放宽）。约定只说"0.5 起、不封顶"。把上限改成 1.0 和 4.0 各试过一次（只跑了快速模式，结果没有留在 `out/` 里）：1.0 时窗口内的根数明显更少，4.0 时只多 1 根、最高的弯接近 3 mm。
2. **基线先补 SDCLK、再补其他线**，目标是让最长的线进窗口。这是上一个原型的结论（先补基准线）。
3. **第 0 字节走 L6、从 SDRAM 封装下面穿过去**，过孔打在两颗芯片的规则区里。参考板 OrangeCrab 是这样做的；另一种走法是在 L1 上绕到 SDRAM 外侧，没有试。
4. **NBL0、NBL1、D2 在 MCU 上边的封装边上就换到 L6**，没有在 L1 上绕。长度一样，L1 的窄条留给了第 1 字节和 SDCLK。
5. **L1 上蛇形的中心线离任何球的中心不小于 0.6 mm**（约定是"L1 上不进球区"，0.6 是我取的数）。
6. **"扫过的面积"这个指标是我加的**，约定的是凸包、外包矩形和窄条宽度。

## 没验证的

- 板子没有在 KiCad 界面里打开过，只用 `kicad-cli` 和 pcbnew 脚本检查过。
- L4 到 L6 的过孔高度（0.2572 mm）复查时用一根打了三个孔的线实测过，和 DRC 一致；现在留下的方案里没有用这种过孔的。
- 第 0 字节在 L6 上从 SDRAM 封装下面穿过：正式板上这里还有 SDRAM 其他 38 根信号和电源球的过孔，这块板上没有，所以封装下面的空地比正式板多。MCU 下面同理。
- 蛇形的电气影响（腿之间的耦合）没有算，只按几何长度。
- SDRAM 的球图取自调研，这次只核对了球名和位置与 KiCad 封装一致，没有重新对规格书。

## 文件

| 路径 | 作用 |
|---|---|
| `build.py` | 一条命令构建一个方案；`--fast` 只算长度和间距；`--summary` 生成 `out/summary.md` |
| `variants/<方案>/routes.py` | 一个方案的全部内容：换位表、走线、蛇形、每根线为什么这样走 |
| `lib/` | 共用代码：建板、画蛇形、量长度、检查、指标、出图。给写方案的 agent 看的说明在 `lib/README.md`（英文） |
| `base/` | 空的六层板、工程文件、规则文件 |
| `references/` | 开工前收集的参考图和笔记 |
| `out/<方案>/` | 构建结果：板子、`metrics.json`、`tune.txt`、图 |
| `review/remeasure.py` | 复查用的独立脚本：不用 `lib/`、不用 pcbnew，直接读板文件重新量长度、过孔数、面积、间距、线形、球号和换位表，和 `metrics.json` 逐项对照；`python review/remeasure.py <方案>`，没有出入时打印 `FINDINGS (0)` |

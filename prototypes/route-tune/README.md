# 原型：走线和等长一起规划，对比占用的空间（一次性，看完即弃）

对应 [原型：走线和等长一起规划，对比占用的空间](https://github.com/immorcoding/PCB/issues/21)。只存在于分支 `prototype/route-tune`，不合并。

**要回答的问题**：走线之前先算每根线要补多少、再决定走法（协调版），比“先把线全部走完、再逐根找直线段补蛇形”（基线）能省多少地方；协调版的样子你认不认可。

同一块板（MCU 和 SDRAM 的位置不动，封装边到边 5 mm，19 根线）做了六块：底板、基线、四块协调版。所有方案用同一套构建脚本、同一张指标表。

本文件里 `<!-- AUTO:… -->` 之间的表格和句子都是 `make_compare.py` 从各方案的 `out/<方案>/metrics.json` 填进来的，不是手抄的；其余文字里不重复这些数字，只指向表。

## 先说结论

**按约定的口径量，协调版没有省地方；它换来的是“做得成”。** 基线在这块板上做不成：走完再补，只有不到一半的线进窗口。四块协调版都是 19 根全进窗口、DRC 干净，但其中三块占的范围比基线大，只有“蛇形全放在 SDRAM 封装下面”的那一块比基线小，而且它的小有一部分是口径带来的。

<!-- AUTO:conclusion -->
- 基线 `1_baseline`（走完再补）：9 / 19 根在窗口内，离 SDCLK 最远的 NBL0 差 +13.872 mm；蛇形 6 处共 38.6 mm；凸包 177.8 mm²，窄条里上下占 17.09 mm。
- `2_detour_first`：19 / 19 根在窗口内。凸包 245.4 mm²，比基线多占 67.6 mm²（38%）；扫过的面积 90.0 mm²，多占 18.5 mm²（26%）；窄条里上下占 21.39 mm，多占 4.30 mm（25%）。蛇形 0 处共 0.0 mm（基线 38.6），绕远合计 234.8 mm（基线 75.6）；SDRAM 封装下面的总线 81.2 mm（基线 75.9）。
- `3_under_sdram`：19 / 19 根在窗口内。凸包 165.9 mm²，比基线省 11.9 mm²（7%）；扫过的面积 57.3 mm²，省 14.2 mm²（20%）；窄条里上下占 15.98 mm，省 1.11 mm（7%）。蛇形 9 处共 33.6 mm（基线 38.6），绕远合计 156.5 mm（基线 75.6）；SDRAM 封装下面的总线 201.8 mm（基线 75.9）。
- `4_combined`：19 / 19 根在窗口内。凸包 240.1 mm²，比基线多占 62.3 mm²（35%）；扫过的面积 95.8 mm²，多占 24.2 mm²（34%）；窄条里上下占 18.20 mm，多占 1.11 mm（6%）。蛇形 7 处共 26.6 mm（基线 38.6），绕远合计 194.3 mm（基线 75.6）；SDRAM 封装下面的总线 105.3 mm（基线 75.9）。
- `4b_combined_p05`：19 / 19 根在窗口内。凸包 240.1 mm²，比基线多占 62.3 mm²（35%）；扫过的面积 95.3 mm²，多占 23.8 mm²（33%）；窄条里上下占 18.20 mm，多占 1.11 mm（6%）。蛇形 7 处共 27.7 mm（基线 38.6），绕远合计 194.3 mm（基线 75.6）；SDRAM 封装下面的总线 106.6 mm（基线 75.9）。

这些数怎么读：

- **基线的面积是“没做完”的面积。** 它还有十根线在窗口外面，要是真补齐（这块板上补不齐），占的地方只会更大，大多少没法量。所以上面的“多占”是拿达标的板和没达标的板比。
- **为什么基线做不成**：底板上最长和最短的线相差太多（见最后的“底板的自然长度”表），连直连距离的差都是窗口宽度的三倍。要进窗口，时钟和最短的几根各要补二十毫米左右，而两颗芯片之间规则区外的直线段只有三毫米上下，旁边还夹着邻线。这不是蛇形参数能解决的，只能在走线时解决。
- **空间三项（凸包、外包矩形、窄条里上下占）只数两颗封装外形以外的铜。** `3_under_sdram` 把线和蛇形挪到了 SDRAM 封装下面，所以它在这三项上小；代价列在“SDRAM 封装下面的总线”那一栏，是基线的两倍半以上。而且它的凸包对口径很敏感：有一根线贴着封装上沿、在外形线里面一点点走，把封装外形内缩 0.1 mm 重算，它的凸包就比基线大了（“各方案占的空间”表的第五列）。**老实的说法是：没有一块协调版的凸包确实比基线小。**
- **凸包和窄条宽度对蛇形不敏感。** 这块板上有三根线（NBL0、NBL1、D2）从 MCU 上边绕下来，本来就把窄条从上到下占满了。蛇形和线距的变化主要反映在“扫过的面积”上。
- **哪种手段出了多少力**见下面“长度是怎么凑出来的”：三块带蛇形的协调版里，比底板多出来的长度有七成以上来自走法（绕远、换层），蛇形只补零头。真正起决定作用的有三件事，都是走线之前定的：
  1. **先压最长的一根**（NBL0 或对调后的 NBL1 改成一条 45° 斜线从 SDRAM 封装下面直穿），窗口整体下移，其余每根线都少补一截。四块协调版都这样做了。
  2. **缺得多的线成束绕远**（十毫米以上的不用蛇形），缺得少的线各放一块等高蛇形。
  3. **蛇形的位置先留出来**（SDRAM 封装下面的 L4、L6，或窄条里专门让出来的一段），不是走完再找。
- **腿间距 0.3 和 0.5**（`4_combined` 对 `4b_combined_p05`，走线完全相同）：两种都放得下、都是 19 根进窗口，占的范围一样（蛇形都在预留的位置里）。0.5 的弯更高、离邻线更近，行距窄的地方只能用最矮的弯；每补 1 mm 占的地见“每一块蛇形”表下面的合计。

## 怎么看

- **对比页**：双击 `compare.html`。默认是“并排”：同一个取景、同一个比例、同一层，几个方案排成一行。上面的按钮换组、换取景（整组线 / 两颗芯片之间 / SDRAM 封装下面 / MCU 下方）、换层（三层叠在一起 / L1 / L4 / L6）；键盘 ← → 换组，↑ ↓ 换层，`[` `]` 换取景。点任意一张图进入那个方案的“单张 + 表”。图下面是指标表（每个方案一列）和每个方案逐根的表，最后一列是“这根线为什么这样走”。页面跟随系统的深色 / 浅色，右上角的按钮可以切换。
- **KiCad**：打开 `out/<方案>/routetune.kicad_pro`（路径见下面的方案表）。板子已经由 `kicad-cli` 重新铺铜并保存。蛇形在 KiCad 里是普通的线段加圆弧（AD 里相当于手画的 Track + Arc），不是“调整图形”对象；规则区相当于 AD 的 Room。
- **图**：L1 红、L4 蓝、L6 绿；灰色实线框是封装外形，绿色虚线是规则区；每根线的名字标在它自己的线上。对比页用的图是 `out/<方案>/cmp_<取景>_<层>.png`，各方案取景和比例完全相同。各方案目录里另有它自己的局部图（取景各不相同，不能跨方案比大小）。图只作定性参考，数字看表（PROC-14）。
- **每个方案的完整结果**：`out/<方案>/tune.txt`；各方案并排的另一张表 `out/summary.md`。
- **重建**：`D:/KiCad/bin/python.exe build.py <方案>`（十几秒），然后 `D:/KiCad/bin/python.exe make_compare.py`（约半分钟，重画对比图、重写对比页和本文件的表）。KiCad 开着那块板时脚本会停下不写，先关掉。

- `0_base` 是基线的起点，本身不是候选方案：19 根线按最顺的路走完，不考虑等长。
- `1_baseline` 是上一个原型（[issue 15](https://github.com/immorcoding/PCB/issues/15)）的做法：底板的走线一根不动，先把 SDCLK 往“最长的一根减 2.5 mm”补，补到放不下为止，再把低于窗口下限的线逐根补。蛇形只放在规则区外、不短于 2.5 mm 的直线段上。
- `2_detour_first`：只靠走法。两个字节通道在 SDRAM 一侧对调，三束线按“要补多少”排内外圈，从 SDRAM 下边绕进去。一处蛇形都没有。
- `3_under_sdram`：第 1 字节和时钟在 L4 上排成九行“梯子”伸到 SDRAM 封装下面，每行的直线就是这根线预留的补线位置；窄条里没有蛇形、没有过孔，L1 在窄条里是空的。
- `4_combined`：缺十毫米以上的八根在 L1 上分两束各绕一个 U 形弯；缺几毫米的七根各放一块等高蛇形，六块在 SDRAM 封装下面的 L6，一块在窄条正中专门留出来的 L4 直线上。数据线腿间距 0.3。
- `4b_combined_p05`：和 `4_combined` 同一份走线，只把所有蛇形的腿间距改成 0.5。

每块协调版的换位表、做法、要你看一眼的地方、计划和实际的差别，都在它自己的 `variants/<方案>/README.md` 和 `PLAN.md` 里。

## 用的约定

和你定过的（各方案都一样）：

- 六层 JLC06161H-3313E：L1 信号，L2 地，L3 电源（不走信号），L4 信号，L5 地，L6 信号。板上的叠层带真实厚度，长度含过孔高度。
- MCU `STM32H743IIK6`（UFBGA176+25）在左，SDRAM `IS42S32800J`（90 球 BGA）在右，封装边到边 5 mm，位置和 [上一个原型](../length-tuning/README.md) 相同，所有方案都不动。`2_detour_first` 的线伸到了 SDRAM 下边以下，板框够大，没有改。
- 19 根线：`FMC_D0`–`FMC_D15`、`FMC_NBL0`、`FMC_NBL1`（接 SDRAM 的 DQM0、DQM1）、`FMC_SDCLK`。没有原理图，网络直接指定在焊盘上。**SDCLK 上没有放串联电阻**（正式板上会有）。
- 两个规则区（封装外形外扩 1 mm，所有铜层）：区内线宽 0.09、间距 0.09、过孔 0.30/0.15；区外线宽 0.1016、间距 0.127。线宽在出规则区边 0.3 mm 的直线上换。
- MCU 外两圈的球在 L1 出，内两圈用狗骨孔走 L4；SDRAM 的球都能在 L1 上走到；L6 也可以走线。每根线的过孔目标 2 个、上限 3 个。
- 换位只在 SDRAM 一侧：字节内换位，两个字节通道可以对调（DQM 跟着通道）。每个方案的换位表在它的 `tune.txt` 第二列和它自己的说明里。
- 等长要求：每根线对 SDCLK 在 ±2.5 mm 以内（是窗口，不是补到一样长），每根不超过 60 mm。SDCLK 和别的线一样处理，可以画蛇形，也可以靠把它加长来让长线进窗口。长度由 KiCad 的 DRC 量（探针规则）。
- 蛇形由脚本画成线段加圆弧，不用 45° 梯形。腿间距（相邻两条腿的中心距）：SDCLK 0.5 mm，数据和 DQM 按方案是 0.3 或 0.5 mm；圆弧半径是腿间距的一半；摆幅 0.5 mm 起。蛇形可以放在 SDRAM 封装下面的 L4、L6（那里线宽 0.09）；L1 上不进球区。
- **等高（2026-11-17 更正后的约定）**：同一个蛇形块（一段直线上的一串弯）里各弯等高，单侧双侧都一样；不同的块、不同的线可以不一样高，没有全板统一的高度；例外只有一种：被邻线的蛇形挡住的地方，面对它的弯可以矮，或者把块拆成两段各自等高；不为凑准长度留矮的尾弯，改调整块的高度。
- 线形：只有 0°/45°/90° 的线段加蛇形的圆弧；没有锐角、直角、T 形接头；同层不交叉。

## 审查的人查出了什么、改了什么

每块协调版搭完以后由另一个 agent 独立审查：用自己写的脚本（`review/` 下，不用 `lib/`，把板文件当文本读，自己跑 DRC 长度探针）重量一遍，再逐张看图。细节在各方案自己的 `README.md` 里，这里只列结论。

- **数字**：长度、过孔数、直连、凸包、窄条宽度、换位表、线宽、同层交叉、块内等高都对得上。这次汇总时又对六块板各跑了一遍 `review/remeasure.py`，结果见最后的“构建用时和独立重量”表。
- **`2_detour_first`**：绕 MCU 右上角的三根斜线原来是“两根加一根”，间距不等，改成三根等距并进一束。说明里和板子对不上的几句改了。
- **`3_under_sdram`**：D2 斜线末端原来有一块硬塞在两个过孔之间的小蛇形，改成 D2、D3 在同一字节内对调球位，蛇形去掉了。审查指出凸包那个数靠的是一根线在封装外形线里面 0.05 mm（见上面“先说结论”）；“绕远”里有一大块是过孔高度；`PLAN.md` 其实是事后补写的。搭建过程中完整构建的 DRC 抓到过一次 17 条孔间距违规（快速模式查不到这一条，见“没验证的”）。
- **`4_combined`**：走线没改。说明里三处不准的说法改了（D3、D6 是沿球行正下方走而不是走行间；D15 缺的量；窄条里放不下蛇形的原因）。审查补了几条你看图时会注意到的：折回后最靠外的 D15 和 SDCLK 有很长一段在 SDRAM 规则区的边带里，线宽是 0.09；D4 的那块只有两个最矮的弯，像个小疙瘩；L6 上四块蛇形左右不齐。
- **基线**：没有改走线。汇总时发现它有不等高的块（见上面“各方案等高的例外”），没有改。
- **公平性**：审查认为线、位置、约定都一样，比较本身是公平的；要注意的两点就是上面说的“基线没做完”和“空间指标不数封装下面的铜”。

## 没验证的

- **没有一块板在 KiCad 界面里打开过**，只用 `kicad-cli` 和 pcbnew 脚本检查过，图都是脚本画的。
- **SDCLK 上没有串联电阻。** 正式板上有，它会把时钟分成两段，还要占窄条里的地方。
- **只有 57 根 SDRAM 线里的 19 根。** SDRAM 封装下面在这块板上大半是空的；正式板上那里还有地址、控制、高 16 位数据的球和过孔，还有电源和地的过孔。`3_under_sdram` 和 `4_combined` 用的正是这块空地，**它们证明的是“放得下、放了以后窄条里干净”，不是“正式板上照搬就行”**。MCU 下面同理。
- 蛇形和并行线的电气影响（腿之间的耦合、L1 和 L6 上下重叠的线、封装下面几毫米长的并行线）没有算，只按几何长度。
- 换不换字节通道，只有 `2_detour_first` 真的按对调走了一遍；其余方案只按直连距离比过。
- 快速模式（`build.py --fast`）和线束工具不查“孔壁到别的铜 0.2 mm”这一条，只有完整构建的 DRC 查。
- L4 到 L6 的过孔高度复查时实测过一次，留下的方案里没有用这种过孔。
- SDRAM 的球图取自调研，只核对了球名和位置与 KiCad 封装一致，没有重新对规格书。
- 基线没有按“块内等高”重做；基线补齐以后会占多大没法量。
- `4_combined` 路线定下来之前改了几轮，没有留下记录。

## 要你答的四个问题

问题取自 [issue 21](https://github.com/immorcoding/PCB/issues/21) 的“用户看完要答的”。每个问题下面是相关的证据和我的建议，决定由你做。

### 1. 协调版的样子认不认可，省下的空间够不够

- **证据**：对比页第一组（基线和三种协调做法），取景选“整组线”和“两颗芯片之间”。数字见“各方案占的空间”表：按约定的口径没有省，三块多占，一块略省但靠的是封装下面。四块都做到了基线做不到的 19 根进窗口。
- **我的看法**：在 5 mm 间距、这 19 根线上，“省空间”这个目标不成立，协调的收益是能不能做成。三种样子里：
  - `2_detour_first` 最整齐（全是等距线束、没有蛇形），但兜的圈最大，SDRAM 下边以下要留出一大块空地。
  - `3_under_sdram` 窄条最干净，但把 SDRAM 封装下面用满了，正式板上最可能走不通。
  - `4_combined` 介于两者之间，最显眼的毛病是 SDCLK 在 U 形弯顶上单独高出一截，以及时钟有很长一段是 0.09 的细线。
- **建议**：不要选其中一块照搬。认可的应该是做法（见第 2、4 题），正式板上 57 根线一起做线序草图（RTE-13）时再定样子。如果要在三块里挑一个方向，我建议 `4_combined` 的分工（缺得多的成束绕远，缺得少的在预留位置放一块等高蛇形），因为它对封装下面的占用比 `3_under_sdram` 少一半左右，兜的圈比 `2_detour_first` 小。

### 2. 协调靠什么实现最顺

- **证据**（来自各方案的 `README.md` “计划和实际差在哪”一节）：三块协调版的大局（换不换通道、哪根定窗口、谁在内圈、谁靠绕远谁靠蛇形、蛇形放哪）都是走线之前算出来的，第一次带蛇形的构建就全部或大部分进了窗口；之后都还要“改一下、量一下”好几轮，其中一半左右是看图以后为了好看改的，另有一次是手算漏了过孔高度、一次是漏了孔间距规则。`2_detour_first` 和 `3_under_sdram` 各记了十轮上下；`4_combined` 没留记录。快速模式一轮几秒，完整构建十几秒（见“构建用时和独立重量”表），轮数不是负担。
- **建议**：三种方式不是三选一，而是分工：
  - **脚本先算**：自然长度、每根缺多少、窗口由哪一根定、每块蛇形的弯数和摆幅。这些算得准，不该靠试。
  - **关键的几根由人指定**：定窗口的最长那一根怎么走、缺得多的线成几束、在哪里绕、蛇形预留在哪。这是拓扑，脚本不会自己想出来，这次也都是在计划里写死的。
  - **量一轮调一轮**只用来收尾（U 形弯的深度、行的位置这几个旋钮），迭代几轮可以接受，但每轮必须跑完整的 DRC，不能只信快速模式。

### 3. 特意绕远的线看着是否别扭，有没有宁可画蛇形也不绕远的情况

- **证据**（看图）：
  - 成束绕远的：`2_detour_first` 的两束 U 形（“整组线”取景，L1 和 L6），`4_combined` 的两束 U 形（L1）。
  - 单根绕远的：`2_detour_first` 的 D3（L4，一根线沿窄条走到底再兜回来）；`3_under_sdram` 的 D3（L4，单独绕着 SDRAM 走一圈）和 D11、D12 的 V 形；`4_combined` 的 SDCLK 顶上单独高出的一截。审查的人都把这几处标成了“要用户判断”。
  - 对照：`4_combined` 里 D10 也是单独一根，用的是窄条里预留的一块蛇形而不是绕远。
- **建议**：成束（三根以上、等距并行）的绕远看着是线束，可以接受；**单根线为了凑长度绕出去的，改用蛇形**。时钟尤其不要为了绕远走进规则区的边带变成细线。你看图以后如果觉得成束的 U 形弯也别扭，那缺十毫米以上的线就只剩“加大封装间距”这一条路，这块板上蛇形放不下这么多。

### 4. 预留的补线空间按什么规则给

- **证据**：“每一块蛇形”表给出了每块实际占的长和宽，以及每补 1 mm 占多少地（0.3 和 0.5 腿间距各一组）。`3_under_sdram` 是每根线统一留一行，结果是行多了以后上面的行离球越来越远，绕远本身成了长度的大头，而且最下面几行其实用不着蛇形；`4_combined` 是按缺的量给，只有七根线留了位置。底板上每根线缺多少见最后一张表，从零到二十多毫米不等，统一留一段不是太多就是不够。
- **建议**：**按要补的量算，不统一留。** 具体可以写成：
  - 走线前由脚本算出每根线对窗口下沿缺多少。
  - 缺得多的（这次的分界在十毫米左右）不留蛇形位置，归到绕远的线束里。
  - 缺得少的每根留一段直线：长度 = 腿间距 ×（弯数 + 1）再加两头各 0.35 mm，宽度 = 摆幅加到邻线的间距；摆幅先按 0.6–0.9 mm（参考板的范围）取，由要补的量解出弯数。
  - 预留的位置优先放在封装下面的内层或背面，其次是窄条里专门让出来的一段；留在哪要和电源、地的过孔位置一起定。
  - 本来就在窗口里的线不留。

  这条和现行的 RTE-2（“走线时就在旁边留出补长的空间”）一致，只是把“留多少”写成了算法。分界取多少、摆幅取多少，要在正式板的线序草图上再验证一次。

## 指标的定义（所有方案同一个脚本 `lib/metrics.py` 算）

| 指标 | 定义 |
|---|---|
| 长度 | KiCad 的 DRC 量到的长度（探针规则）：焊盘中心到焊盘中心的走线（直线和圆弧）加每个过孔在它连接的两层之间的高度 |
| 比 SDCLK | 这根线的长度减 SDCLK 的长度；绝对值不超过 2.5 算在窗口内 |
| 直连最短 | 两个焊盘中心之间只走 0°/45°/90° 的最短平面距离，不管任何障碍，不算板厚 |
| 蛇形补的 | 这根线上所有蛇形多出来的长度（画出来的长度减去被它替换掉的那段直线） |
| 不算蛇形的走线 | 长度减蛇形补的，也就是把蛇形拉直以后的长度（含过孔高度） |
| 绕远 | 不算蛇形的走线减直连最短：靠走法本身多出来的长度（含过孔高度）。表里另把过孔高度和平面内的部分分开列 |
| SDRAM 下的蛇形 | 蛇形补的长度里，蛇形的铜落在 SDRAM 封装外形以内的那一部分（按铜的长度比例折算） |
| 凸包面积 | 两颗封装外形以外的所有总线铜（走线、圆弧、蛇形的中心线和过孔中心，三层叠在一个平面上）的凸包面积 |
| 外包矩形 | 同一批点的外包矩形的宽和高 |
| 窄条里上下占（通道宽度） | 两个规则区之间那一条（x 19–22 mm）里，总线中心线在 y 方向（垂直于 MCU 到 SDRAM 的方向）的最大值减最小值；另有分层的 |
| 扫过的面积 | 同一批铜各自外扩“半个线宽加 0.127 mm”之后合并起来的面积，0.05 mm 栅格；有三层合并和分层两种。约定里没有这一项，是搭地基时加的 |
| 各层铜面积 | 每层总线走线的长度乘线宽之和（在 `metrics.json` 里，表里没列） |

三项补充的数不在 `metrics.json` 里，是 `make_compare.py` 对每块板用同一段代码从板文件量的，存在 `out/compare_extra.json`：

| 补充项 | 定义 |
|---|---|
| SDRAM 封装下面的总线长度 | 总线走线（不含过孔）中心线落在 SDRAM 封装外形以内的长度，分层 |
| 封装外形内缩 0.1 mm 再算的凸包 | 把两颗封装的外形各向里缩 0.1 mm，再用 `lib/metrics.py` 的同一个函数算凸包。用来看凸包有多依赖“刚好在外形线里面”的铜 |
| 独立重量的出入 | `review/remeasure.py` 重新量长度、过孔数、面积、间距、线形、球号和换位表，和 `metrics.json` 不一致的项数 |

检查项（`metrics.json` 的 `checks`）：DRC 各类条数（`kicad-cli pcb drc --refill-zones --severity-all`，未连接必须是 0）；规则生效检查（往板的副本上放一个直角拐弯，看 DRC 报不报）；每条长度规则单独探测时是否匹配到 19 根线；`track_shape.py` 的五项；脚本从板文件按纳米坐标量的间距、每根线是不是一条从球到球的单线、蛇形离别的网络和规则区边最近多少、拐点到第一个圆弧最短多少。

## 我自己定的、没有和你约定过的

1. **基线的摆幅上限 2.0 mm**（先按 1.0 找，放不下才放宽）。上限改成 1.0 和 4.0 各用快速模式试过一次，结果没有留：1.0 时进窗口的更少，4.0 时只多一根。
2. **基线先补 SDCLK、再补其他线**（上一个原型的结论）。
3. **底板的第 0 字节走 L6、从 SDRAM 封装下面穿过去**，过孔打在两颗芯片的规则区里（参考板 OrangeCrab 的做法）。
4. **L1 上蛇形的中心线离任何球的中心不小于 0.6 mm**（约定是“L1 上不进球区”，0.6 是我取的数）。
5. **“扫过的面积”和三项补充的数**是加的，约定的是凸包、外包矩形和窄条宽度。
6. **协调版蛇形的目标**是窗口下沿往上留一点余量，不是补到和 SDCLK 一样长；各方案离窗口边最近还剩多少见指标表第三行，都只有零点几毫米。正式板上余量要留多大需要你定。

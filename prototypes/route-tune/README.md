# 原型：走线和等长一起规划，对比占用的空间（一次性，看完即弃）

对应 [原型：走线和等长一起规划，对比占用的空间](https://github.com/immorcoding/PCB/issues/21)。只存在于分支 `prototype/route-tune`，不合并。

**要回答的问题**：走线之前先算每根线要补多少、再决定走法（协调版），比“先把线全部走完、再逐根找直线段补蛇形”（基线）能省多少地方；协调版的样子你认不认可。

同一块板（MCU 和 SDRAM 的位置不动，封装边到边 5 mm，19 根线）做了七块：底板、基线、五块协调版。所有方案用同一套构建脚本、同一张指标表。前六块是第一轮；你 2026-11-17 看完以后说“综合版大部分不错，但线不要特意绕远，蛇形反而集中”，第七块 `5_no_detour` 就是照这句话把 `4_combined` 改出来的。

本文件里 `<!-- AUTO:… -->` 之间的表格和句子都是 `make_compare.py` 从各方案的 `out/<方案>/metrics.json` 填进来的，不是手抄的；其余文字里不重复这些数字，只指向表。

## 先说结论

**协调换来的首先是“做得成”；去掉特意绕远以后（`5_no_detour`），板面上占的地方也回到了基线的水平，凸包和扫过的面积都比 `4_combined` 小四分之一以上。** 你说的“蛇形比绕远集中”在这块板上量出来是成立的，但有条件，见下面“去掉绕远以后”。

- 基线在这块板上做不成：走完再补，只有不到一半的线进窗口。五块协调版都是 19 根全进窗口、DRC 干净。
- 第一轮的四块协调版里，三块占的范围比基线大，只有“蛇形全放在 SDRAM 封装下面”的 `3_under_sdram` 比基线小，而且它的小有一部分是口径带来的。
- `5_no_detour` 把 `4_combined` 表层的两个 U 形弯和时钟单独绕的那一圈去掉，缺的长度全部用等高的蛇形块补。空间三项都比 `4_combined` 小，也都不比基线大；代价是蛇形多了两倍多、SDRAM 封装下面压的线更多、多了六个过孔，时钟那一块蛇形很显眼。数字在下面两个表里。

这张表怎么读才公平：

- **比 `4_combined` 是两块做完的板在比**，差别是实的：省下来的主要是表层（没有线再伸到 MCU 上边以北和 MCU 左下角）。
- **比基线是做完的板和没做完的板在比。** 基线只有不到一半的线进窗口；`5_no_detour` 全部进了窗口，占的地方还略小。扫过的面积只差百分之一，当作持平，不当作“省了”。
- **空间三项不数封装下面的铜。** `5_no_detour` 有一部分蛇形在 SDRAM 封装下面（表里“其中补在 SDRAM 封装下面的”一行），这部分不计入凸包、窄条和扫过的面积，代价记在“SDRAM 封装下面的总线”一行。它的凸包不靠“刚好在外形线里面”的铜：外形内缩 0.1 mm 重算，结论不变（`3_under_sdram` 在这一项上会翻过来）。
- **蛇形块本身并不比成束的线密多少。** “每补 1 mm 占多少”那一句是蛇形块自己的外包矩形，不含到邻线的间距；成束 U 形弯每补 1 mm 占多少没有单独量过（`5_no_detour` 的说明里按线距粗算过，和数据蛇形差不多）。量得到的是“整块板的账”那三行：同样是把长度凑进窗口，`5_no_detour` 在板面上多扫的面积比 `4_combined` 少得多。
- **省下来的地方来自两点**：蛇形可以摆在总线本来就要经过的范围里（MCU 下方那四行原来就要从那里过），U 形弯只能伸到范围外面去；另有一部分蛇形进了 SDRAM 封装下面，不占板面。所以结论带条件：旁边有现成的直线、或者封装下面有空的时候，蛇形省地方；两样都没有的时候它和绕远一样占地。时钟就是例子，它那一块并不小，只是没有伸到 MCU 上边去。
- **还剩下的绕远**：有四根线（D10、D15、D14、D13）为了把蛇形放进 SDRAM 封装下面，过孔打在比球更靠东的地方，再从表层折回来，全部在封装底下，不占板面。这算不算“特意绕远”要你定，见最后的问题。逐根的清单在 `variants/5_no_detour/README.md` 的“还剩下的绕远”。

### 第一轮各方案的数怎么读

- **基线的面积是“没做完”的面积。** 它还有十根线在窗口外面，要是真补齐（这块板上补不齐），占的地方只会更大，大多少没法量。所以上面的“多占”是拿达标的板和没达标的板比。
- **为什么基线做不成**：底板上最长和最短的线相差太多（见最后的“底板的自然长度”表），连直连距离的差都是窗口宽度的三倍。要进窗口，时钟和最短的几根各要补二十毫米左右，而两颗芯片之间规则区外的直线段只有三毫米上下，旁边还夹着邻线。这不是蛇形参数能解决的，只能在走线时解决。
- **空间三项（凸包、外包矩形、窄条里上下占）只数两颗封装外形以外的铜。** `3_under_sdram` 把线和蛇形挪到了 SDRAM 封装下面，所以它在这三项上小；代价列在“SDRAM 封装下面的总线”那一栏，是基线的两倍半以上。而且它的凸包对口径很敏感：有一根线贴着封装上沿、在外形线里面一点点走，把封装外形内缩 0.1 mm 重算，它的凸包就比基线大了（“各方案占的空间”表的第五列）。**老实的说法是：第一轮的四块协调版里，没有一块的凸包确实比基线小；`5_no_detour` 两种口径下都比基线小几个百分点。**
- **凸包和窄条宽度对蛇形不敏感。** 这块板上有三根线（NBL0、NBL1、D2）从 MCU 上边绕下来，本来就把窄条从上到下占满了。蛇形和线距的变化主要反映在“扫过的面积”上。
- **哪种手段出了多少力**见下面“长度是怎么凑出来的”：第一轮三块带蛇形的协调版里，比底板多出来的长度有七成以上来自走法（绕远、换层），蛇形只补零头；`5_no_detour` 反过来，多出来的长度大半靠蛇形。真正起决定作用的有三件事，都是走线之前定的：
  1. **先压最长的一根**（NBL0 或对调后的 NBL1 改成一条 45° 斜线从 SDRAM 封装下面直穿），窗口整体下移，其余每根线都少补一截。五块协调版都这样做了。
  2. **缺的长度怎么分**：第一轮是缺得多的线成束绕远（十毫米以上的不用蛇形），缺得少的线各放一块等高蛇形；`5_no_detour` 是全部用蛇形，按每根缺的量给每块定弯数和摆幅。
  3. **蛇形的位置先留出来**（SDRAM 封装下面的 L4、L6，MCU 下方表层的一段并行直线，或窄条里专门让出来的一段），不是走完再找。
- **腿间距 0.3 和 0.5**（`4_combined` 对 `4b_combined_p05`，走线完全相同）：两种都放得下、都是 19 根进窗口，占的范围一样（蛇形都在预留的位置里）。0.5 的弯更高、离邻线更近，行距窄的地方只能用最矮的弯；每补 1 mm 占的地见“每一块蛇形”表下面的合计。

## 怎么看

- **对比页**：双击 `compare.html`。默认是“并排”：同一个取景、同一个比例、同一层，几个方案排成一行；打开时的第一组是基线、`4_combined`、`5_no_detour` 三块。上面的按钮换组、换取景（整组线 / 两颗芯片之间 / SDRAM 封装下面 / MCU 下方）、换层（三层叠在一起 / L1 / L4 / L6）；键盘 ← → 换组，↑ ↓ 换层，`[` `]` 换取景。点任意一张图进入那个方案的“单张 + 表”。图下面是指标表（每个方案一列）和每个方案逐根的表，最后一列是“这根线为什么这样走”。页面跟随系统的深色 / 浅色，右上角的按钮可以切换。
- **KiCad**：打开 `out/<方案>/routetune.kicad_pro`（路径见下面的方案表）。板子已经由 `kicad-cli` 重新铺铜并保存。蛇形在 KiCad 里是普通的线段加圆弧（AD 里相当于手画的 Track + Arc），不是“调整图形”对象；规则区相当于 AD 的 Room。
- **图**：L1 红、L4 蓝、L6 绿；灰色实线框是封装外形，绿色虚线是规则区；每根线的名字标在它自己的线上。对比页用的图是 `out/<方案>/cmp_<取景>_<层>.png`，各方案取景和比例完全相同。各方案目录里另有它自己的局部图（取景各不相同，不能跨方案比大小）。图只作定性参考，数字看表（PROC-14）。
- **每个方案的完整结果**：`out/<方案>/tune.txt`；各方案并排的另一张表 `out/summary.md`。
- **重建**：`D:/KiCad/bin/python.exe build.py <方案>`（十几秒），然后 `D:/KiCad/bin/python.exe make_compare.py`（约半分钟，重画对比图、重写对比页和本文件的表）。KiCad 开着那块板时脚本会停下不写，先关掉。

- `0_base` 是基线的起点，本身不是候选方案：19 根线按最顺的路走完，不考虑等长。
- `1_baseline` 是上一个原型（[issue 15](https://github.com/immorcoding/PCB/issues/15)）的做法：底板的走线一根不动，先把 SDCLK 往“最长的一根减 2.5 mm”补，补到放不下为止，再把低于窗口下限的线逐根补。蛇形只放在规则区外、不短于 2.5 mm 的直线段上。
- `2_detour_first`：只靠走法。两个字节通道在 SDRAM 一侧对调，三束线按“要补多少”排内外圈，从 SDRAM 下边绕进去。一处蛇形都没有。
- `3_under_sdram`：第 1 字节和时钟在 L4 上排成九行“梯子”伸到 SDRAM 封装下面，每行的直线就是这根线预留的补线位置；窄条里没有蛇形、没有过孔，L1 在窄条里是空的。
- `4_combined`：缺十毫米以上的八根在 L1 上分两束各绕一个 U 形弯；缺几毫米的七根各放一块等高蛇形，六块在 SDRAM 封装下面的 L6，一块在窄条正中专门留出来的 L4 直线上。数据线腿间距 0.3。
- `4b_combined_p05`：和 `4_combined` 同一份走线，只把所有蛇形的腿间距改成 0.5。
- `5_no_detour`（你看完前六块以后加的）：`4_combined` 去掉特意绕远的线。蛇形分三处：SDRAM 西半边底下的一把“梳子”（L4 四行、L6 四块，同一条起始线）；MCU 下方表层的四行，每行一块，同起同止；时钟单独一块双侧蛇形，在窄条正中。第 0 字节和 NBL0、NBL1、D2、D3 基本沿用 `4_combined` 的走法。数据线腿间距 0.3，时钟 0.5。没有做 0.5 的对照版。

每块协调版的换位表、做法、要你看一眼的地方、计划和实际的差别，都在它自己的 `variants/<方案>/README.md` 和 `PLAN.md` 里。

## 用的约定

和你定过的（各方案都一样）：

- 六层 JLC06161H-3313E：L1 信号，L2 地，L3 电源（不走信号），L4 信号，L5 地，L6 信号。板上的叠层带真实厚度，长度含过孔高度。
- MCU `STM32H743IIK6`（UFBGA176+25）在左，SDRAM `IS42S32800J`（90 球 BGA）在右，封装边到边 5 mm，位置和 [上一个原型](../length-tuning/README.md) 相同，所有方案都不动。`2_detour_first` 的线伸到了 SDRAM 下边以下，板框够大，没有改。
- 19 根线：`FMC_D0`–`FMC_D15`、`FMC_NBL0`、`FMC_NBL1`（接 SDRAM 的 DQM0、DQM1）、`FMC_SDCLK`。没有原理图，网络直接指定在焊盘上。**SDCLK 上没有放串联电阻**（正式板上会有）。
- 两个规则区（封装外形外扩 1 mm，所有铜层）：区内线宽 0.09、间距 0.09、过孔 0.30/0.15；区外线宽 0.1016、间距 0.127。线宽在出规则区边 0.3 mm 的直线上换。
- MCU 外两圈的球在 L1 出，内两圈用狗骨孔走 L4；SDRAM 的球都能在 L1 上走到；L6 也可以走线。每根线的过孔目标 2 个、上限 3 个。
- 换位只在 SDRAM 一侧：字节内换位，两个字节通道可以对调（DQM 跟着通道）。每个方案的换位表在它的 `tune.txt` 第二列和它自己的说明里。
- 等长要求：每根线对 SDCLK 在 ±2.5 mm 以内（是窗口，不是补到一样长），每根不超过 60 mm。SDCLK 和别的线一样处理，可以画蛇形，也可以靠把它加长来让长线进窗口。长度由 KiCad 的 DRC 量（探针规则）。
- 蛇形由脚本画成线段加圆弧，不用 45° 梯形。腿间距（相邻两条腿的中心距）：SDCLK 0.5 mm，数据和 DQM 按方案是 0.3 或 0.5 mm；圆弧半径是腿间距的一半；摆幅 0.5 mm 起。蛇形可以放在 SDRAM 封装下面的 L4、L6（那里线宽 0.09）；L1 上不进球区。
- **等高（2026-11-17 更正后的约定）**：同一个蛇形块（一段直线上的一串弯）里各弯等高，单侧双侧都一样；不同的块、不同的线可以不一样高，没有全板统一的高度；例外只有一种：被邻线的蛇形挡住的地方，面对它的弯可以矮，或者把块拆成两段各自等高；不为凑准长度留矮的尾弯，改调整块的高度。
- 线形：只有 0°/45°/90° 的线段加蛇形的圆弧；没有锐角、直角、T 形接头；同层不交叉。

## 还要你答的问题

### 1. 协调靠什么实现：脚本先算、量一轮调一轮、还是你指定关键的线束

- **证据**：
  - 五块协调版的大局（哪根定窗口、哪几根放哪个区、谁靠蛇形、蛇形放哪、换位表）都是走线之前算出来的，之后没有变过。`5_no_detour` 第一次带蛇形能跑通的构建就是 18 / 19。
  - 之后都还要“改一下、量一下”几轮。`5_no_detour` 搭建用了 5 轮，审查又改了 1 轮；`2_detour_first` 和 `3_under_sdram` 各十轮上下；`4_combined` 没留记录。改的内容一半左右是放不下（线束工具报错、蛇形离拐弯太近），另一半是看图以后为了整齐改的，DRC 都报不出来。
  - 快速模式一轮几秒，完整构建半分钟以内（见“构建用时和独立重量”表），轮数本身不是负担。
  - 动手前手算的自然长度不准（`5_no_detour` 的 `PLAN.md` 记了有六根差一毫米以上），但不影响结果，因为蛇形的摆幅是脚本拿走完以后量到的长度解的。
- **我的建议**（三种方式是分工，不是三选一）：
  - **脚本先算**：自然长度、每根缺多少、窗口由哪一根定、每块蛇形的弯数和摆幅。
  - **拓扑由我在计划里写死，不先给你点头**（你已经定了不设这一关）：定窗口的那一根怎么走、哪几根放哪个区、蛇形预留在哪。
  - **量一轮调一轮只用来收尾**，每轮跑完整的 DRC，不只信快速模式；达标或到轮数上限就停，交给你看图。
- **还要你定的**：
  - 轮数上限用什么式子。暂定式和它在 19 根时给出的轮数见第 2 题那张表后面的最后一行；现在有两个数据点（第一轮约 11 轮，`5_no_detour` 6 轮），都在上限以内。你还没有确认这个式子。
  - “达标”里要不要包含“看着整齐”。这次审查改的四处都是 DRC 干净但看着挤或不齐的；如果要包含，需要把它们写成能量的条件（见第 2 题最后两条）。
  - 你要不要保留“指定关键线束”的权利，比如在线序草图上直接圈出哪几根放在哪。我的建议是保留，但不作为必经的一关。

### 2. 预留的补线空间按什么规则给

`5_no_detour` 用的规则（你已同意“按要补的量算，不统一留”，这里是具体算法）：

1. **先压总量**：把最长的一根走到最短，时钟定在“最长的一根减去窗口半宽再留一点余量”，数据线的目标定在窗口下沿往上留同样的余量。
2. **算每根缺多少**：目标减去这根线不带蛇形时的长度。本来就在窗口里的不留；只差零点几毫米的不放一两个弯的小疙瘩，要么靠第 1 步让它自然进窗口，要么和邻线放一样大的一块。
3. **每根留一段直线，放一块等高的蛇形**（公式见表下面）。预留的直线 = 块占的直线 + 两头各留一段。两头留多少：搭建时按画法的下限 0.35 mm，审查看图后改成 0.7 mm 以上。
4. **朝弯的一侧到邻线的中心距** ≥ 摆幅 + 线宽 + 0.19 mm（蛇形到别的铜的画法限制）。
5. **两种解法**：
   - 行距是定的（SDRAM 封装下面，跟着球距取 1.0 mm）：摆幅有上限，由要补的量解出弯数，也就是要留多长的直线；一组里按最多的那根统一留。
   - 直线长度是定的（MCU 下方表层那四行）：弯数由直线定，由要补的量解出摆幅，行距 = 下面一行的摆幅 + 固定空隙。
6. **放在哪**：优先放在总线本来就要经过的并行直线上，其次是封装下面的内层或背面，最后才是窄条里专门让出来的一段。

- **公式本身是准的**：弯数、摆幅给定以后，占多长的直线、补多少长度，和板上量到的对得上（表的最后一列）。
- **“缺多少”的估计不准，但不要紧**：动手前估的总量比实际多一成左右，单根有差一毫米以上的；因为摆幅是走完以后解的，估计只用来定弯数和预留的直线，这次每个区定下来的弯数都够用。
- **预留的直线第一次没留够**：SDRAM 封装下面有两行第一次只够放四个弯，MCU 下方那四行第一次按七个弯算，摆幅太高，都在头两轮里改了。原因是预留的时候没把拐弯和进过孔的斜线占掉的那一截算进去。
- **“两头留多少”这条规则原来没有**：按下限放，DRC 干净，但蛇形顶着拐弯，审查改成了 0.7 mm 以上。建议写进规则。
- **行距按“摆幅 + 固定空隙”给，比等行距整齐**（块与块之间的缝一样宽），也是审查改出来的。建议写进规则。
- **规则管不到的地方**：球在封装靠外几列的线，封装下面的直线不够长，蛇形要放进去，过孔就必须越过球再折回（见第 4 题）。时钟缺得多、腿间距又大，一块的面积是定的，放在哪都显眼。

**还要你定的**：这套算法是否就按上面六条写进规则（RTE-2）；两头留多少、固定空隙取多少（这次是 0.7 和 0.30）；余量留多大（这次上下各留三百多微米，是我们定的数）。

### 3. 布局阶段要不要动 SDRAM 的位置或窗口

- **证据**：这块板上两颗芯片的位置是给定的，19 根线的直连最短距离从最短到最长相差十五毫米多（“底板的自然长度”表的最后一句），是窗口宽度的三倍。所以不管哪种做法，都要补出一百多毫米的长度（“长度是怎么凑出来的”表），`5_no_detour` 的十三块蛇形就是这么来的。蛇形摆得再整齐，这个量是布局决定的，走线阶段减不掉。
- **你已经定的**：布局阶段把 SDRAM 的位置和旋转当变量，线序草图除了不交叉和总长，还要比“各线最短路径相差多少”，先把这个差距压小；窗口保持 ±2.5 mm，摆位压不下来才考虑放宽或按组等长。
- **还要你定的**：
  - **差距压到多少算够**。建议用“要补的总长度”和“最缺的一根缺多少”两个数做布局阶段的验收项，由线序草图的脚本算；具体的门槛这个原型给不出来（只有一个摆位），需要在正式板上换两三个摆位比一次。
  - **压不下来时先动哪一个**：按字节通道分组等长（每组对自己的选通或时钟），还是放宽窗口。这块板上两个字节通道的直连距离本身就差一截，按组等长可能比放宽窗口更有效；没有验证。
  - **要不要现在就用这个原型试一个摆位**（比如 SDRAM 旋转 90° 或上下挪几毫米），看要补的总量能降多少。这是一次新的构建，不在这次的范围里；你要的话可以加一块。

### 4. 看 `5_no_detour` 的图以后要你定的

- **封装下面“多走一截再折回”算不算特意绕远。** D10、D15、D14、D13 四根为了把蛇形放进 SDRAM 封装下面，过孔比球更靠东，再从表层折回，全在封装底下，不占板面。要完全去掉，这四块蛇形得回到板面上，而窄条和 MCU 下方已经放不下。我的建议：不占板面的折回不算“特意绕远”，但要在说明里逐根列出来。
- **时钟那一块能不能接受。** 它是板上最显眼的东西：横着把窄条的可用宽度铺满。另一种做法是把时钟也放进梳子（两个过孔，封装下面走一段细线再折回），窄条里的表层就空了；只算过，没做。你要的话可以补一块对比。
- **MCU 下方四块蛇形高度不一样。** 每块自己是等高的（符合约定），但四块并排、高度各不相同，参考板上一组通常一样高。改成四块同高可行（多补出来的长度仍在窗口内），代价是最下面一行再往下挪一点、D8 多一个小折；没做，等你看图决定。
- **腿间距 0.5 的对照版要不要做。** SDRAM 封装下面按现在的行距放不下同样的量，要重排。

## 指标的定义（所有方案同一个脚本 `lib/metrics.py` 算）

| 指标 | 定义 |
|---|---|
| 长度 | KiCad 的 DRC 量到的长度（探针规则）：焊盘中心到焊盘中心的走线（直线和圆弧）加每个过孔在它连接的两层之间的高度 |
| 比 SDCLK | 这根线的长度减 SDCLK 的长度；绝对值不超过 2.5 算在窗口内 |
| 直连最短 | 两个焊盘中心之间只走 0°/45°/90° 的最短平面距离，不管任何障碍，不算板厚 |
| 蛇形补的 | 这根线上所有蛇形多出来的长度（画出来的长度减去被它替换掉的那段直线） |
| 不算蛇形的走线 | 长度减蛇形补的，也就是把蛇形拉直以后的长度（含过孔高度） |
| 绕远 | 不算蛇形的走线减直连最短：靠走法本身多出来的长度（含过孔高度）。表里另把过孔高度和平面内的部分分开列 |
| SDRAM 下的蛇形 | 蛇形补的长度里，蛇形的铜落在 SDRAM 封装外形以内的那一部分（按铜的长度比例折算） |
| 凸包面积 | 两颗封装外形以外的所有总线铜（走线、圆弧、蛇形的中心线和过孔中心，三层叠在一个平面上）的凸包面积 |
| 外包矩形 | 同一批点的外包矩形的宽和高 |
| 窄条里上下占（通道宽度） | 两个规则区之间那一条（x 19–22 mm）里，总线中心线在 y 方向（垂直于 MCU 到 SDRAM 的方向）的最大值减最小值；另有分层的 |
| 扫过的面积 | 同一批铜各自外扩“半个线宽加 0.127 mm”之后合并起来的面积，0.05 mm 栅格；有三层合并和分层两种。约定里没有这一项，是搭地基时加的 |
| 各层铜面积 | 每层总线走线的长度乘线宽之和（在 `metrics.json` 里，表里没列） |

三项补充的数不在 `metrics.json` 里，是 `make_compare.py` 对每块板用同一段代码从板文件量的，存在 `out/compare_extra.json`：

| 补充项 | 定义 |
|---|---|
| SDRAM 封装下面的总线长度 | 总线走线（不含过孔）中心线落在 SDRAM 封装外形以内的长度，分层 |
| 封装外形内缩 0.1 mm 再算的凸包 | 把两颗封装的外形各向里缩 0.1 mm，再用 `lib/metrics.py` 的同一个函数算凸包。用来看凸包有多依赖“刚好在外形线里面”的铜 |
| 独立重量的出入 | `review/remeasure.py` 重新量长度、过孔数、面积、间距、线形、球号和换位表，和 `metrics.json` 不一致的项数 |

检查项（`metrics.json` 的 `checks`）：DRC 各类条数（`kicad-cli pcb drc --refill-zones --severity-all`，未连接必须是 0）；规则生效检查（往板的副本上放一个直角拐弯，看 DRC 报不报）；每条长度规则单独探测时是否匹配到 19 根线；`track_shape.py` 的五项；脚本从板文件按纳米坐标量的间距、每根线是不是一条从球到球的单线、蛇形离别的网络和规则区边最近多少、拐点到第一个圆弧最短多少。

## 我自己定的、没有和你约定过的

1. **基线的摆幅上限 2.0 mm**（先按 1.0 找，放不下才放宽）。上限改成 1.0 和 4.0 各用快速模式试过一次，结果没有留：1.0 时进窗口的更少，4.0 时只多一根。
2. **基线先补 SDCLK、再补其他线**（上一个原型的结论）。
3. **底板的第 0 字节走 L6、从 SDRAM 封装下面穿过去**，过孔打在两颗芯片的规则区里（参考板 OrangeCrab 的做法）。
4. **L1 上蛇形的中心线离任何球的中心不小于 0.6 mm**（约定是“L1 上不进球区”，0.6 是我取的数）。
5. **“扫过的面积”和三项补充的数**是加的，约定的是凸包、外包矩形和窄条宽度。
6. **协调版蛇形的目标**是窗口下沿往上留一点余量，不是补到和 SDCLK 一样长；各方案离窗口边最近还剩多少见指标表第三行，都只有零点几毫米。正式板上余量要留多大需要你定。

# 实测：KiCad 10.0.8 的差分对 DRC（E1–E5）

票：[#44](https://github.com/immorcoding/PCB/issues/44)（地图 [#26](https://github.com/immorcoding/PCB/issues/26)）。日期 2026-11-26，KiCad 10.0.8，Windows 11。
分支 `research/diff-pair-drc`，只存档不合并。要核对的说法来自分支 `research/diff-pair-tooling` 的 `docs/research/diff-pair-tooling.md`（下称“调研”）第 3.4 节和第 9 节，那些都是读源码得出的，没有运行过。

## 怎么跑的

```
python docs/research/diff-pair-drc/run.py          # 在仓库根目录，系统 python
```

`run.py` 经 `core.heavy` 一次只跑一个重活：

1. `D:\KiCad\bin\python.exe docs/research/diff-pair-drc/make_board.py board templates/C-bga-065/C-bga-065.kicad_pro`：写夹具板 `board/dpdrc.kicad_pcb`（两层，线宽 0.1，对内中心距 0.25 即间隙 0.15，网络类 Default 只改了线宽、间距 0.1 和差分对参数）和 `board/predict.json`。坐标全部是整数 nm，直接写进 `VECTOR2I`；板文件里保留到 nm（例：`/E1B_N` 从 `7.911612 0.088389` 到 `12.911613 5.088389`）。
2. 每套规则一次：`kicad-cli pcb drc --severity-all --units mm --format json -o results/<套>.json work/<套>/dpdrc.kicad_pcb`，规则文件在 `rules/<套>.kicad_dru`。
3. `results/summary.txt`：每套规则里和差分对有关的报告原文，后面附 `predict.json` 的预测。

结束时没有 KiCad 进程在跑（`heavy.running()` 为空）。

同一套跑了两遍（第二遍只改了预测里圆弧耦合长度的算法），两遍的 94 个报告值逐个相同；报告的顺序和引用的是哪一段不同，因为 pcbnew 每次给对象新的 uuid。

预测是按调研第 3.4 节的读法算的：两段同层、方向向量整数叉积恰为 0、不共线、投影重叠，间隙在窗口内才算耦合；非耦合 = max(P 长, N 长) − Σ耦合重叠长度。**预测不含“两段之间没有别的铜”这一条**，所以 DRC 和预测不一样的地方就指向它。

每个用例是一对独立的网络 `/<用例>_P`、`/<用例>_N`，所有用例在同一块板上。读数的办法：`diff_pair_uncoupled (max 0.0001mm)`，没有报告即非耦合 ≤ 0.0001 mm，有报告就带实际值；`skew`、`length` 同样用极小的上限逼出实际值。

| 规则套 | 内容 |
|---|---|
| rs1_window_unc | `diff_pair_gap (min 0.14mm)(max 0.2mm)` + `diff_pair_uncoupled (max 0.0001mm)` |
| rs2_minonly_unc | `diff_pair_gap (min 0.14mm)`（无上限）+ `diff_pair_uncoupled (max 0.0001mm)` |
| rs3_window_only | 只有间隙窗口 |
| rs4_window_unc_loose | 间隙窗口 + `diff_pair_uncoupled (max 50mm)`（预算不会超） |
| rs5_skew_length | E3、E4 的 `skew (within_diff_pairs)` 和 `length` 探针 |

## 结果

### E1 整数偏移和“平行”的判定

| 用例 | 几何 | 调研的预测 | DRC（rs1、rs2） |
|---|---|---|---|
| E1A | 45°，N = P + 同一整数向量 | 耦合 | 耦合（无报告） |
| E1B | 45°，浮点中线、P/N 各端分别取整，两线方向差 (1, 0) nm | 非耦合 7.0711 | **耦合**（无报告） |
| E1C | 45°，N 末端故意偏 1 nm | 非耦合 7.0711 | **耦合** |
| E1D | 水平 10 mm，N 末端偏 1 nm | 非耦合 10 | **耦合** |
| E1G / E1H | 两个 45° 弯，按角平分线逐点取整 / 整数偏移线求交 | 0.2071 / 0.2071 | 0.2071 / 0.2071 |

调研说“叉积必须恰为 0”不成立。扫一遍偏差找门槛（N 末端横向偏 d，背离 P）：

| 组 | 长度 | 仍耦合的最大偏差 | 开始非耦合 |
|---|---|---|---|
| E1T 水平 | 10 mm | 1000 nm（1.0e-4 rad） | 3000 nm（3e-4 rad） |
| E1U 水平 | 1 mm | 100 nm（1.0e-4 rad） | 300 nm（3e-4 rad） |
| E1V 45° | 7.07 mm | x 偏 300 nm（垂直分量 3.0e-5 rad） | x 偏 1000 nm（1.0e-4 rad） |

门槛是**角度**，约 1e-4 rad（0.006°），和段长无关；正好 1e-4 时一例耦合一例不耦合。取整到 nm 带来的角度误差是 1 nm / 段长：0.1 mm 的段是 1e-5，离门槛差十倍。

E1G、E1H 的 0.2071 是两个 45° 弯的内外线长差：每个 45° 弯损失 S·tan 22.5°（中心距 S = 0.25 时 0.1036 mm）的耦合长度。

### E2 补偿凸起和圆弧

| 用例 | 几何（凸起都在 P 上，基线 10 mm） | 预测 rs1 / rs2 | DRC rs1 | DRC rs2 | 间隙报告（rs1、rs3、rs4） |
|---|---|---|---|---|---|
| E2Z | 直线对照 | 0 / 0 | 0 | 0 | 无 |
| E2A | 矩形向外，竖腿，高 0.3，顶 0.6 | 1.2 / 0.6 | 1.2000 | **1.2000** | **无** |
| E2B | 矩形向内，高 0.02（间隙 0.15→0.13） | 0.64 / 0.64 | 0.6400 | 0.6400 | 0.13 < 最小 0.14 |
| E2C | 梯形向外，45° 腿，高 0.3，顶 0.6 | 1.4485 / 0.8485 | 1.4485 | 0.8485 | 0.45 > 最大 0.2 |
| E2D | 圆角向外（`tune.py` 的形状：r 0.1 四分之一圆弧、腿 0.1、直顶 0.6） | 1.4283 / 0.8283 | 1.4283 | 0.8283 | 0.45 > 最大 0.2 |
| E2E | 半圆向外，r 0.3 | 0.9425 / 0.9425 | 0.9425 | 0.9425 | 无 |
| E2F | 90° 转弯，同心圆弧 r 1.125 / 0.875 | 0.3927 / 0.3927（耦合长度按内弧，见下） | 0.3927 | 0.3927 | 无 |
| E2G | 90° 转弯，P 圆弧、N 两段 45° 倒角 | 1.7671 | 1.7671 | 1.7671 | 无 |

- 顶边是直线、和 N 平行的向外凸起（梯形、圆角）：顶边**算耦合**，间隙 0.45。有间隙上限时报 `diff_pair_gap_out_of_range` 并计入非耦合；没有上限时它算耦合，非耦合反而少。
- 矩形竖腿凸起（E2A）：顶边**根本不算耦合**，有没有上限都一样，也不报间隙。原因见 E5：挡住它的是 P 自己在凸起起点处的基线。
- 向内凸起（E2B）：顶边耦合，间隙变小，低于下限就报错。
- 圆弧只和同心圆弧配对（E2F 耦合，耦合长度按内弧算，非耦合 = 外弧 − 内弧 = θ·S）；圆弧和直线不配对（E2G 整段弧都算非耦合）；半圆凸起（E2E）不报间隙，代价是整段弧长。

### E3 pad-to-die 和焊盘内的折线（rs5）

| 用例 | 几何 | DRC 的 P 长 | DRC 的 skew（N 对 P） |
|---|---|---|---|
| E3A | 两根直线 10 mm，P 起点焊盘 `die_length` 1.0 | 11.0000 | −1.0000 |
| E3B | P 在 0.6 mm 焊盘里折一下：(0,0)→(0.25,−0.25)→(0.5,0)→(10,0)，几何 10.2071 | **10.1434** | −0.1434 |
| E3C | 同样的折线，焊盘 0.3 mm，拐点在盘外 | 10.2071 | −0.2071 |

pad-to-die 计入 `length` 和 `skew`；焊盘里的那段按“中心到出盘点的直线”折算（E3B：中心到 (0.3, −0.2) 0.3606 + 0.2828 + 9.5 = 10.1434），和调研第 3.2 节、K53 一致。

### E4 `skew (within_diff_pairs)` 只命中一根网络（rs5）

| 用例 | 规则条件 | 长度（`length` 探针） | skew 报告 |
|---|---|---|---|
| E4A | `A.NetName == '/E4A_P'` | P 10.0000，N 11.0000 | **无**（静默跳过） |
| E4B | `A.inDiffPair('/E4B')`（对照） | 同上 | −1.0000 |
| E4C | 只有 `/E4C_P`，板上没有 `/E4C_N` | P 10.0000 | 无 |

### E5 成对换层、两线之间的铜

| 用例 | 几何 | 预测 | DRC rs1 | DRC rs2 |
|---|---|---|---|---|
| E5A | F 层成对线 45° 张开到过孔对（中心距 0.7），B 层收回；两个 GND 过孔在外侧 | 0.6364 | 0.6364 | 0.6364 |
| E5D | 宽对（间隙 0.75），中间无过孔（对照） | — / 0 | 10（间隙越界） | 0 |
| E5C | 宽对，GND 过孔在两线中间 x = 5 | — / 0 | 10 | **0** |
| E5E / E5F | 宽对，GND 过孔在 x = 0.3 / 9.7（过孔不压到端点） | — / 0 | 10 | **0** |
| E5G | 宽对，GND 过孔圆心在 x = 0（重叠段起点） | — / 0 | 10 | **10.0000** |
| E5H | 宽对，GND 过孔圆心在 x = 10（重叠段终点） | — / 0 | 10 | **0** |

- 过孔不计长度；张开段不平行，全算非耦合（E5A 正好是两段张开线 2 × 0.3182）；不同层上碰巧平行的两段不配对。
- “两段之间有没有别的铜”只在**重叠段的一端**查一条横线（这里是起点 x = 0）：中间、靠近两端但不压线的过孔都不挡；压在起点的过孔让整段 10 mm 不算耦合。E2A 的矩形凸起就是这样被 P 自己的基线挡掉的。两根线方向相反时查哪一端，没有测。

### 报告规则（rs3、rs4 对 rs1）

- 间隙越界**总是报**：rs3（无非耦合规则）和 rs4（非耦合预算 50 mm 没超）都报同样的 8 条。调研第 3.4 节“同时写两条规则、预算没超就不报间隙”不成立。
- 非耦合也超限时（rs1、rs2），每条间隙越界在报告里**出现两次**（rs1 共 16 条 = 2 × 8）。

## 对调研的更正

1. 第 0 节第 3 条、第 3.4 节“必须恰为 0”：实际门槛是约 1e-4 rad 的角度，不需要整数精确平行。
2. 第 3.4 节“判定”最后一条：间隙越界不受非耦合预算影响，总是报。
3. 第 3.4 节“补偿凸起”：向外凸起的顶边是否被挡，取决于重叠段起点那条横线上有没有铜；矩形竖腿被挡（不算耦合、不报间隙），梯形和圆角不被挡（算耦合，有上限就报间隙越界）。
4. 其余说法实测成立：只认同心圆弧、圆弧和直线不配对、过孔不计入非耦合的总长、不同层不配对、pad-to-die 计入、焊盘内折线折算、`within_diff_pairs` 只命中一根时静默跳过。

## 对差分对工具的直接含义（交给“定差分对工具的接口、指标和基准”那张票）

1. 几何不用整数精确构造：每个顶点各自取整到 nm 即可，只要段长 ≥ 0.1 mm（角度误差 ≤ 1e-5，门槛的十分之一）。工具自查可以卡“P/N 对应段方向差 < 1e-5 rad”。
2. 非耦合预算可以在构建时算准：本篇的预测模型（同层、平行、投影重叠、间隙窗口）加上“重叠段起点横线上无他铜”，在全部用例上和 DRC 一致到 0.0001 mm。每个 45° 弯花 S·tan 22.5°，同心圆弧转弯花 θ·S，成对换层花全部张开段。
3. 补偿凸起和 `diff_pair_gap` 的上限冲突：有上限时，顶边是直线的向外凸起（包括 `tune.py` 现在的圆角形状）一律报间隙越界，而且不论预算。可选的路：规则里不写间隙上限、只靠非耦合预算和工具自查；或者凸起只用圆弧（半圆）；矩形竖腿能躲开但靠的是上面那个只查一端的细节，不稳。由那张票定。
4. 凸起只向外：向内凸起使间隙变小，低于下限就报错。
5. `skew (within_diff_pairs)` 的条件只命中一根时不报任何东西：规则生成器要自查每对的两根都被同一条规则命中（`rules.dru_match` 一类的检查），不能靠 DRC 发现。
6. 对内偏差的长度口径和调研第 3.2 节相同（pad-to-die 计入、焊盘内折线折算），工具的长度要按这个算，或者像 K53 那样把拐点放到盘外。

## 文件

- `make_board.py`：夹具板和预测（KiCad 的 python）。
- `run.py`：构建、五套 DRC、汇总（系统 python，经 `core.heavy`）。
- `board/`：生成的板、工程文件、`predict.json`。
- `rules/`：五套规则文件。
- `results/`：五份 DRC 的 JSON 原文和 `summary.txt`。
